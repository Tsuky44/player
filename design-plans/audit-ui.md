# Audit UI — Playeur (app Flutter : desktop, mobile, web)

## Design language

- **Surface auditée** : l'application Flutter `app/lib` — un seul binaire déployé sur macOS/Windows, Android et web. Le chemin tracé part de `main.dart` → `MainShell` (`screens/shell/main_shell.dart`) et couvre les quatre onglets (Accueil, Films, Séries, Demandes), les fiches détail, le login et le chrome partagé (`widgets/global/`). Desktop/mobile/web ne sont **pas** trois bases de code : ce sont deux branches de rendu du même arbre, décidées par `AppLayout.isWide(context)` (seuil 900 px, `utils/responsive.dart:22`). Le web tombe donc dans la branche desktop ou mobile selon la largeur de fenêtre — tout écart entre les deux branches est visible sur web aussi.
- **Sources de design** :
  - `PROJECT_DESIGN.md` — brief courant et **gouvernant**. Il se déclare aligné sur `app/lib/theme/app_colors.dart` (§12 Implementation Mapping) et ses valeurs correspondent exactement au code (`#0A0A0A`, `#141414`, `#1C1C1C`, `#0A84FF`, `#F5F5F7`/`#A1A1A6`/`#6E6E73`, `#30D158`/`#FF9F0A`/`#FF453A`).
  - `design.md` — décrit par `PROJECT_DESIGN.md` §4 comme le « incumbent brief » dont certains points sont explicitement **non transférables**. Utilisé ici seulement là où il ne contredit pas `PROJECT_DESIGN.md`.
  - `app/lib/theme/app_colors.dart` + `app_theme.dart` — les tokens réellement chargés à l'exécution.
- **Décisions documentées retenues** :
  - §6 : « Constraints: **no `#E50914`** ; accent ≤ ~5% surface ; pas de purple/neon »
  - §11 Don't : « Netflix red, purple gradients, neon glow »
  - §2 : « Patterns to remove or avoid: rouge Netflix, glow purple »
  - §8 Media cards : « Radius 12–14 ; Hover desktop: 1px white 16% stroke »
  - §11 Do : « Align shell + player + login on same tokens »
- **Owners gouvernants et consommateurs** : `AppColors`/`AppTheme` (tokens) → `glass_chrome.dart` (chrome desktop), `main_shell.dart` (shell + nav + menu compte), `media_card.dart` / `media_poster.dart` / `continue_watching_card.dart` (grilles et rows), `screens/requests/**` (onglet Demandes).
- **Exceptions explicites** : `None documented`.

## Improve first

**Finding 1.** C'est le seul écart qui touche l'identité de la marque plutôt qu'un détail de composant : le rouge Netflix est interdit par trois passages distincts du brief courant, il occupe la position la plus visible de l'interface (coin haut-gauche, présent en permanence sur desktop et web), et il coexiste avec une seconde marque bleue sur mobile — donc corriger d'un seul geste supprime une violation de contrat explicite *et* unifie les trois plateformes. Le correctif est mécanique et sans ambiguïté : un exemplaire du traitement cible existe déjà dans `app_theme.dart`.

## Observations écartées

Ces points sont ressortis de l'inspection mais **n'ont pas passé le gate de preuve** — je les note pour transparence, pas comme findings :

- **Onglets de nav desktop en pilule pleine.** `PROJECT_DESIGN.md` §8 dit « accent underline/dot **not filled pill blob** » ; `GlassNavTab` (`glass_chrome.dart:247`) rend exactement une pilule blanche à 14 %. Le contrat est explicite mais propose deux corrections possibles (soulignement *ou* point), donc la correction n'est pas déterminée par la preuve.
- **`design.md` a un frontmatter qui contredit sa propre prose.** Les tokens YAML en tête (`surface: #121414`, `primary: #c9c6c5`, police `Geist`) n'ont aucun rapport avec la palette décrite plus bas ni avec `app_colors.dart`, et aucun code Dart ne lit ce fichier. C'est un risque de documentation, pas un défaut d'interface.
- **`player_hud_overlay.dart` utilise `#007AFF` au lieu de `#0A84FF`** (`player_hud_overlay.dart:68`) — mais `PlayerHudOverlay` n'est instancié nulle part (`ModularControlsLayer` est le seul HUD monté, `player_screen.dart:1237`). Preuve runtime absente : le code est mort.
- **Libellé de déconnexion incohérent** — « Déconnexion » (`home_screen.dart:361`) contre « Se déconnecter » (`main_shell.dart:398`, `settings_screen.dart:567`), plus deux présentations d'avatar différentes (`CircleAvatar` contre `GlassIconButton`). C'est un vrai doublon de menu compte, mais le correctif se recoupe avec le Finding 1 (les deux tiennent au fait que `_HomeOverlayBar` réimplémente le chrome du shell) ; à traiter dans le même plan.
- **Accessibilité et sémantique** (contrastes, cibles tactiles, focus clavier) : hors périmètre de cet audit, non demandé.
